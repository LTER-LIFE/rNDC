# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`rNDC` is an R package (Apache-2.0, fork maintained for LTER-LIFE) with wrappers for retrieving data from LTER-LIFE's **NatureDataCube** (a STAC API) plus two related sources: **AgroDataCube** (REST) and **GroenMonitor** (WCS GeoServer). Unqualified calls to imported packages must be listed as `@importFrom` in `R/rNDC-package.R` (no blanket imports, to avoid masking warnings); otherwise use `pkg::fn`. `DESCRIPTION` `Imports` lists the packages.

## Commands

Run R through the conda env: `conda run -n base_r Rscript -e '...'`.

- Run all tests: `devtools::test()`; a single file: `devtools::test(filter = "ndc_roi")` (matches `tests/testthat/test-<filter>.R`). Tests are offline: HTTP is stubbed at transport level with `webmockr` (httr adapter; `httptest2` only supports httr2, which this package does not use). `local_stac_api()` in `tests/testthat/helper-fixtures.R` stubs a STAC API at `https://example.org/api/` (landing page, `/search`, `/collections`, token required: `"t"`). Webmockr does not write `httr::write_disk()` targets, so raster tests replace `stac_download_one` with a fake writer.
- Regenerate docs and `NAMESPACE`: `roxygen2::roxygenise()`. `NAMESPACE` and `man/` are **generated**; never edit them by hand. Imports are declared as `@importFrom` tags in `R/rNDC-package.R`, and every exported function needs `@export` plus a roxygen block.
- Full check: build a copy and run `R CMD build` + `R CMD check --no-manual`.
- Load during development: `devtools::load_all()`.
- Example notebooks are in `examples/` (R kernel; `01`-`04` for the high-level functions, `advanced/` for the raw STAC/REST/WCS interfaces; see `examples/README.md`). They are excluded from the build via `.Rbuildignore`, `library(rNDC)` in them loads the *installed* package, and they need network access plus `NDC_TOKEN`/`ADC_TOKEN`. Run them as plain R with `Rscript tools/run_notebooks.R [names]` (uses `devtools::load_all()`, stops at the first error). `Rscript tools/regenerate_notebooks.R [names]` re-evaluates the cells and saves the outputs (text, messages, plots) in the notebooks; it refuses to write a notebook whose output holds a token. IRkernel is not installed in `base_r`, so saved outputs are generated by evaluating the cells with the `evaluate` package (`tools/regenerate_notebooks.R`); keep execution counts sequential and outputs free of tokens.
- Live API tests (`tests/testthat/test-live.R`) are skipped unless `RNDC_LIVE_TESTS=true` (plus both tokens): `RNDC_LIVE_TESTS=true conda run -n base_r Rscript -e 'devtools::test(filter = "live")'`.
- CI (`.github/workflows/`): `R-CMD-check.yaml` runs the offline check on push/PR; `live-checks.yaml` runs the live tests and notebooks weekly (default branch) or on manual dispatch, using the `NDC_TOKEN`/`ADC_TOKEN` repository secrets. Repo: https://github.com/LTER-LIFE/rNDC.
- Credentials come from env vars: `NDC_TOKEN` (default for `ndc_get`, landuse and nitrogen functions). AgroDataCube functions (`adc_*`, the meteo functions) use `ADC_TOKEN`.
- The NatureDataCube STAC endpoint comes from `ndc_endpoint()` (default: the test server; override with `options(rNDC.endpoint = ...)`).

## Architecture

Code lives in flat `R/*.R` files (R allows no subfolders). The file name starts with the source or layer that the code belongs to, so related files sort together; several small related functions share a file, a long one has its own:

- `ndc_*.R`: the NatureDataCube client and its thematic products (`ndc_get`, `ndc_count`, `ndc_datasets`, `ndc_available`, `ndc_metadata`, `ndc_citation`, `ndc_roi`, `ndc_trange`, `ndc_sites`, `ndc_defaults`, `ndc_external`, `ndc_progress`, `ndc_repeat`, `ndc_landuse`, `ndc_nitrogen`, `ndc_ndvi_stats`, `ndc_ndvi`: `ndc_ndvi_month()`/`_stack()`); `assets_download_wcs.R` keeps its name as an extension of rstac's `assets_download()`.
- `stac_*.R`: building blocks for STAC rasters (`stac_availability`, `stac_metadata`, `stac_wcs`, `stac_raster`; the `stac_*` helpers are documented on one page, `?stac_helpers`, anchored in `stac_metadata.R`, which has to sort first of the three).
- `adc_*.R`: the AgroDataCube (`adc_url`, `adc_get`, `adc_get_all`, `adc_ndvi`, `adc_weather`: the `adc_weather_*` functions and `split_date_range`).
- `gm_*.R`: the GroenMonitor (`gm_url`, `gm_get`, `gm_ndvi`: `gm_ndvi_month()`/`_stack()` and their helpers).
- `utils.R`: what everything shares: `%||%`, the checks of tokens and HTTP errors (`check_token()`, `stop_for_http_error()`) and the machinery of `save_params`/`params_file` (`params_specs` and the functions that write and read the files). `rNDC-package.R` has the imports. The test files have the name of the R file that they test (`test-ndc_get.R` for `ndc_get.R`); the shared fixtures are in `helper-fixtures.R`.

Function names start with the source (`ndc_`, `adc_`, `gm_`, `stac_`) and arguments mean the same everywhere: `roi` (a region, anything `ndc_roi()` accepts), `trange` (a period: one or two dates, `NA` for an open side; `trange_bounds()`/`trange_dates()` read it), `collections` (several ids) or `collection` (exactly one), `station`, `output_dir`/`output_path` (where output goes), `token`, `limit`. `deprecated.R` keeps the names and arguments of rNDC <= 0.5.1 as wrappers that warn (the arguments of functions that kept their name are renamed with `deprecated_argument()`); do not use them in new code, and add a wrapper there when a released name changes.

By data source:

1. **Generic NDC STAC client** (`ndc_*.R`, `assets_download_wcs.R`; the machinery of the parameters files is in `utils.R`, `ndc_repeat()` in `ndc_repeat.R`): `ndc_get()` builds an rstac search against `ndc_endpoint()`, with a Bearer token; the retrieval functions (`ndc_get`, the raster, NDVI and meteo functions, `adc_get`, `adc_get_all`, `gm_get`) take `save_params`/`params_file` to write and read their parameters as JSON (`ndc_params.R`: one format per function, `rNDC-<function>/1`, driven by the table `params_specs`; the file never holds the token or where files go; areas are stored as GeoJSON; arguments of the call override the file, found with `missing()`; the file is written on exit when the function returned without an error, so a recorded argument may be normalised in the function but not changed into something else; `ndc_repeat()` runs a file by its schema). To make another function recordable: add it to `params_specs`, give it the two arguments, and call `params_apply()`/`params_save_when_done()` at its start; the test in `test-params-functions.R` checks the table against the arguments. Its `mode` argument selects the output: raw items, `fetch`, `tibble`, `sf`, `sfc`, `download`, or `download_wcs`. `ndc_roi()` normalizes a RoI (bbox numeric / file path / sf) to EPSG:4326 (for a file with several layers, `layer` chooses one; the first is used, with a warning, otherwise); `ndc_trange()`/`as_rfc3339()` format dates; `ndc_metadata()` (`ndc_metadata.R`, with `ndc_citation()`) reads the collection-level metadata (the items do not repeat it): core fields, the Scientific extension (`sci:doi`, `sci:citation`, `sci:publications`), and one list-column for every other prefixed field, discovered from the data; `ndc_datasets()`/`ndc_count()` list collections and item counts (`ndc_datasets(collections = )` limits them to some collections and skips the request for the list). `ndc_available()` (`ndc_available.R`) lists the datasets with data for an area and/or period: the STAC collections (one `stac_availability()` search, then exact counts when the page was full; the extents in the metadata are NOT used to skip collections, some are stale) plus `ndc_external_datasets()` (`ndc_external.R`: AgroDataCube and GroenMonitor datasets with the static coverage, `verified = FALSE`; the first dates are the single source of truth for the Shiny app too). `stac_availability()` (`stac_availability.R`) tells which collections have items for an area, and for which years, with ONE search over all of them (the collections that a full page may have hidden are counted one by one). Every function that takes a token refuses an empty one up front with the internal `check_token()` (`http_helpers.R`, which also has `stop_for_http_error()`: it raises errors of class `rNDC_http_error` with the HTTP `status`, so that callers can tell e.g. a 404 from a server failure). STAC assets backed by WCS servers need `assets_download_wcs()`. The conversion/download modes only use the first page of results unless `all_pages = TRUE`. `ndc_ndvi_stats()` (`ndc_ndvi_stats.R`) summarises the `ndvi-*` collections per polygon and month (filtered on the `ndc_id` of the area, since a search also returns the neighbours); `ndc_progress.R` has `ndc_with_progress()`: it sets the options `rNDC.progress` (a `function(message, current, total)`) and `rNDC.interrupt` (a `function()` returning `TRUE` to stop) that the functions with many requests honour through the internal `ndc_progress()` (call it before each request; it reports, then stops with an `rNDC_interrupted` error if asked; without the options it does nothing); `ndc_defaults.R` exports the defaults of the land use/nitrogen rasters and `ndc_landuse_years()` / `ndc_nitrogen_years()` (read from STAC).
2. **Thematic raster retrievers** (`ndc_landuse.R`, `ndc_nitrogen.R`): high-level `ndc_landuse_raster()` / `ndc_nitrogen_raster()` take an AOI, year (and layers), query the STAC API (land use: collection `lgn`; nitrogen: one collection per layer, `ntot`/`nox`/`nh3`), send the year to the search as a time range (`stac_year_trange()`; the items are filtered by layer/year locally as well), download the WCS asset with an AOI subset in EPSG:32631, clip to the AOI and return a `terra` stack. Each file has its own config constants at the top (collection, layers, CRS).
3. **Shared STAC raster helpers** (`stac_metadata.R`, `stac_wcs.R`, `stac_raster.R`; `%||%` is in `utils.R`): the intended common layer (`stac_collect_metadata` (with an optional `trange`), `stac_year_trange`, `stac_download_one` with retries/min-size check, `stac_wcs_subset_suffix`, `stac_clip_raster_to_aoi`, `stac_build_stack`, plus the `%||%` operator; the exported ones are `stac_make_headers`, `stac_collect_metadata`, `stac_year_trange`, `stac_wcs_subset_suffix`, `stac_download_one` and `stac_clip_raster_to_aoi`, the others are internal). `ndc_landuse.R` and `ndc_nitrogen.R` both build on it; AOI normalisation goes through `ndc_roi()`. Prefer the `stac_*` helpers for new raster products.
4. **AgroDataCube REST** (`adc_url.R`, `adc_get.R`, `adc_get_all.R`: all pages of paged requests such as `Fields`) plus meteo helpers built on top (`adc_weather.R`: `adc_weather_station`, `adc_weather_date/period/long_period`, `split_date_range`). `long_period` splits a range into chunks of `by_days` and `rbind`s the sf results.
5. **GroenMonitor WCS** (`gm_url.R`, `gm_get.R`, `gm_ndvi.R`): `gm_ndvi_month()` downloads one daily NDVI coverage per day (`groenmonitor__ndvi_YYYYMMDD`) from `data.groenmonitor.nl` and averages them; `gm_ndvi_stack()` loops over months, calling the same internal helpers (`gm_download_day()`, `gm_download_month()`, `gm_month_mean()`) and aligning the monthly means to one grid. Only a 404 (`NoSuchCoverage`) means "no data for that day"; other failures are retried twice and then raised. Both report one step per day with `ndc_progress()`, use a unique `tempfile()` folder for the daily tiles, and remove it when they end (also when interrupted). The same NDVI can be found through NatureDataCube (`ndc_ndvi.R`): the items of the `ndvi` collection are the daily GroenMonitor coverages, so `ndc_ndvi_month()`/`ndc_ndvi_stack()` search once, download the `wcs` asset of each item with the bounding-box subset (`stac_download_one()`, EPSG:32631) and use `gm_month_mean()` and `ndvi_stack_months()` (`utils.R`, shared with `gm_ndvi_stack()`) for the monthly means, so the result equals the direct download. The GroenMonitor rasters hold digital numbers (NDVI = number / 250, `ndvi_scale`; 0 no data, 1 water): all four raster functions divide the monthly mean by 250 unless `scale = FALSE`. `adc_ndvi()` (`adc_ndvi.R`) is different: the AgroDataCube answers with statistics per field (`ndvi_avg`, `ndvi_stddev`) for ONE date per request, for the fields of a polygon (`adc_get_all("NDVI", ...)`) or for a `fieldid` (valid for one year); no rasters, no field geometries.

Bundled data is in `inst/extdata/` (`study_sites.gpkg` with one layer per site, `nl.gpkg`, `veluwe.gpkg`).

## Gotchas

- Some functions are not exported in NAMESPACE (e.g. `get_nitrogen_stats`, `nitrogen_*` internals); check NAMESPACE before assuming a function is public.
- `aidecl.yaml` is an AI-usage declaration for the project; update it if AI tool usage changes.
