# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`rNDC` is an R package (Apache-2.0, fork maintained for LTER-LIFE) with wrappers for retrieving data from LTER-LIFE's **NatureDataCube** (a STAC API) plus two related sources: **AgroDataCube** (REST) and **GroenMonitor** (WCS GeoServer). Unqualified calls to imported packages must be listed as `@importFrom` in `R/rNDC-package.R` (no blanket imports, to avoid masking warnings); otherwise use `pkg::fn`. `DESCRIPTION` `Imports` lists the packages.

## Commands

Run R through the conda env: `conda run -n base_r Rscript -e '...'`.

- Run all tests: `devtools::test()`; a single file: `devtools::test(filter = "ndc_roi")` (matches `tests/testthat/test-<filter>.R`). Tests are offline: HTTP is stubbed at transport level with `webmockr` (httr adapter; `httptest2` only supports httr2, which this package does not use). `local_stac_api()` in `tests/testthat/helper-fixtures.R` stubs a STAC API at `https://example.org/api/` (landing page, `/search`, `/collections`, token required: `"t"`). Webmockr does not write `httr::write_disk()` targets, so raster tests replace `stac_download_one` with a fake writer.
- Regenerate docs and `NAMESPACE`: `roxygen2::roxygenise()`. `NAMESPACE` and `man/` are **generated**; never edit them by hand. Imports are declared as `@importFrom` tags in `R/rNDC-package.R`, and every exported function needs `@export` plus a roxygen block.
- Full check: build a copy and run `R CMD build` + `R CMD check --no-manual`.
- Load during development: `devtools::load_all()`.
- Example notebooks are in `examples/` (R kernel; `01`-`04` for the high-level functions, `advanced/` for the raw STAC/REST/WCS interfaces; see `examples/README.md`). They are excluded from the build via `.Rbuildignore`, `library(rNDC)` in them loads the *installed* package, and they need network access plus `NDC_TOKEN`/`ADC_TOKEN`. Run them as plain R with `Rscript tools/run_notebooks.R [names]` (uses `devtools::load_all()`, stops at the first error). IRkernel is not installed in `base_r`, so saved outputs were generated by evaluating the cells with the `evaluate` package; keep execution counts sequential and outputs free of tokens.
- Live API tests (`tests/testthat/test-live.R`) are skipped unless `RNDC_LIVE_TESTS=true` (plus both tokens): `RNDC_LIVE_TESTS=true conda run -n base_r Rscript -e 'devtools::test(filter = "live")'`.
- CI (`.github/workflows/`): `R-CMD-check.yaml` runs the offline check on push/PR; `live-checks.yaml` runs the live tests and notebooks weekly (default branch) or on manual dispatch, using the `NDC_TOKEN`/`ADC_TOKEN` repository secrets. Repo: https://github.com/LTER-LIFE/rNDC.
- Credentials come from env vars: `NDC_TOKEN` (default for `ndc_get`, landuse and nitrogen functions). AgroDataCube functions take `token` explicitly.
- The NatureDataCube STAC endpoint comes from `ndc_endpoint()` (default: the test server; override with `options(rNDC.endpoint = ...)`).

## Architecture

Code lives in flat `R/*.R` files, grouped by data source:

1. **Generic NDC STAC client** (`ndc_*.R`, `assets_download_wcs.R`): `ndc_get()` builds an rstac search against `ndc_endpoint()`, with a Bearer token. Its `mode` argument selects the output: raw items, `fetch`, `tibble`, `sf`, `sfc`, `download`, or `download_wcs`. `ndc_roi()` normalizes a RoI (bbox numeric / file path / sf) to EPSG:4326 (for a file with several layers, `layer` chooses one; the first is used, with a warning, otherwise); `ndc_trange()`/`as_rfc3339()` format dates; `ndc_datasets()`/`ndc_count()` list collections and item counts (`ndc_datasets(collections = )` limits them to some collections and skips the request for the list). Every function that takes a token refuses an empty one up front with the internal `check_token()` (`http_helpers.R`, which also has `stop_for_http_error()`: it raises errors of class `rNDC_http_error` with the HTTP `status`, so that callers can tell e.g. a 404 from a server failure). STAC assets backed by WCS servers need `assets_download_wcs()`. The conversion/download modes only use the first page of results unless `all_pages = TRUE`. `get_ndvi_stats()` (`ndvi_stats.R`) summarises the `ndvi-*` collections per polygon and month (filtered on the `ndc_id` of the area, since a search also returns the neighbours); `ndc_progress.R` has `ndc_with_progress()`: it sets the options `rNDC.progress` (a `function(message, current, total)`) and `rNDC.interrupt` (a `function()` returning `TRUE` to stop) that the functions with many requests honour through the internal `ndc_progress()` (call it before each request; it reports, then stops with an `rNDC_interrupted` error if asked; without the options it does nothing); `ndc_defaults.R` exports the defaults of the land use/nitrogen rasters and `ndc_landuse_years()` / `ndc_nitrogen_years()` (read from STAC).
2. **Thematic raster retrievers** (`landuse.R`, `nitrogen.R`): high-level `get_landuse_raster()` / `get_nitrogen_raster()` take an AOI, year (and layers), query the STAC API (land use: collection `lgn`; nitrogen: one collection per layer, `ntot`/`nox`/`nh3`), send the year to the search as a time range (`stac_year_trange()`; the items are filtered by layer/year locally as well), download the WCS asset with an AOI subset in EPSG:32631, clip to the AOI and return a `terra` stack. Each file has its own config constants at the top (collection, layers, CRS).
3. **Shared STAC raster helpers** (`stac_raster_helpers.R`): the intended common layer (`stac_collect_metadata` (with an optional `trange`), `stac_year_trange`, `stac_download_one` with retries/min-size check, `stac_wcs_subset_suffix`, `stac_clip_raster_to_aoi`, `stac_build_stack`, plus the `%||%` operator; the exported ones are `stac_make_headers`, `stac_collect_metadata`, `stac_year_trange`, `stac_wcs_subset_suffix`, `stac_download_one` and `stac_clip_raster_to_aoi`, the others are internal). `landuse.R` and `nitrogen.R` both build on it; AOI normalisation goes through `ndc_roi()`. Prefer the `stac_*` helpers for new raster products.
4. **AgroDataCube REST** (`adc_url.R`, `adc_get.R`, `adc_get_all.R`: all pages of paged requests such as `Fields`) plus meteo helpers built on top (`get_closest_meteostation`, `get_meteo_for_date/period/long_period`, `split_date_range`). `long_period` splits a range into chunks of `by_days` and `rbind`s the sf results.
5. **GroenMonitor WCS** (`gm_url.R`, `gm_get.R`, `gm_ndvi_helpers.R`, `monthly_ndvi.R`, `monthly_ndvi_period.R`): `download_avg_ndvi_month()` downloads one daily NDVI coverage per day (`groenmonitor__ndvi_YYYYMMDD`) from `data.groenmonitor.nl` and averages them; `download_avg_ndvi_stack()` loops over months, calling the same internal helpers (`gm_download_day()`, `gm_download_month()`, `gm_month_mean()`) and aligning the monthly means to one grid. Only a 404 (`NoSuchCoverage`) means "no data for that day"; other failures are retried twice and then raised. Both report one step per day with `ndc_progress()`, use a unique `tempfile()` folder for the daily tiles, and remove it when they end (also when interrupted).

Bundled data is in `inst/extdata/` (`study_sites.gpkg` with one layer per site, `nl.gpkg`, `veluwe.gpkg`).

## Gotchas

- Some functions are not exported in NAMESPACE (e.g. `get_nitrogen_stats`, `nitrogen_*` internals); check NAMESPACE before assuming a function is public.
- `aidecl.yaml` is an AI-usage declaration for the project; update it if AI tool usage changes.
